📊 WHAT IT MEASURES
────────────────────────────────────────────────────────────────────────
  1. Tensor Sharding Time    : GDDR6 DRAM → L1 SRAM (sharded across cores)
  2. Weight Streaming Time   : GDDR6 DRAM → L1 SRAM (weight loading)
  3. NoC Communication Time  : Inter-core data transfers
  4. Overhead Comparison     : Large batch vs Mini-batch scenarios

⚙️  COMMAND OPTIONS
────────────────────────────────────────────────────────────────────────
  --large-batch N        : Large batch size (default: 256)
  --small-batch N        : Small batch size (default: 32)
  --minibatches N        : Number of minibatches (default: 8)
  --in-features N        : Input features (default: 4096)
  --out-features N       : Output features (default: 4096)
  --warmup N             : Warmup iterations (default: 2)
  --iterations N         : Measurement iterations (default: 5)
  --output FILE          : CSV output file
  --enable-tracy         : Enable Tracy profiling

📈 SAMPLE OUTPUT
────────────────────────────────────────────────────────────────────────
  --- Tensor Sharding (DRAM -> L1 SRAM) ---
    Large batch:  1234.567 us
    Mini-batch:   2456.789 us
    Overhead:     1222.222 us  ← Time lost to repeated sharding

  --- Weight Streaming (DRAM -> L1 SRAM) ---
    Large batch:  3456.789 us
    Mini-batch:   5678.901 us
    Overhead:     2222.112 us  ← Time lost to weight reloading

  --- NoC Communication ---
    Large batch:  567.890 us
    Mini-batch:   891.234 us
    Overhead:     323.344 us   ← Time lost to smaller transfers

  Total Overhead: 3767.678 us (71.63%)

🔍 WHAT THE NUMBERS MEAN
────────────────────────────────────────────────────────────────────────
  ✓ Positive Overhead  = Mini-batching is slower (expected)
  ✓ Sharding Overhead  = Cost of distributing data N times vs once
  ✓ Weight Overhead    = Cost of reloading weights N times
  ✓ NoC Overhead       = Cost of many small transfers vs few large ones
  ✓ Total Overhead %   = Overall mini-batch penalty

💡 OPTIMIZATION INSIGHTS
────────────────────────────────────────────────────────────────────────
  IF sharding_overhead is HIGH:
    → Keep data pre-sharded in L1
    → Use async sharding operations
    → Batch sharding operations

  IF weight_streaming_overhead is HIGH:
    → Implement L1 weight caching
    → Use weight pre-fetching
    → Better L1 memory management

  IF noc_comm_overhead is HIGH:
    → Different core grid layouts
    → Larger chunks per transfer
    → Pipeline parallelism to hide NoC latency

🔧 TROUBLESHOOTING
────────────────────────────────────────────────────────────────────────
  ❌ "Device not found"
     → Check: export ARCH_NAME=wormhole_b0
     → Check: source python_env/bin/activate

  ❌ Out of memory
     → Reduce batch sizes: --large-batch 128 --in-features 2048
     → Reduce iterations: --iterations 3

  ❌ Inconsistent timings
     → Increase warmup: --warmup 5
     → Increase iterations: --iterations 20

  ❌ Import errors
     → Ensure in tt-metal directory
     → Check: python research_codes/test_profiling_setup.py
